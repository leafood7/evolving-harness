# 本地可用版本：从启动到反馈

这是可日常使用的原型，不是已经证明稳定收益的自进化系统。本次只整理入口、结果、反馈与排错；实验候选、回归门槛和历史失败保留。

## 启动

当 `evolving-harness` 与 `log-inspector` 是相邻目录时，双击仓库根目录的 `start-log-inspector.cmd`。它使用日志工具现有数据库、local用户、log-inspector项目和DeepSeek模型，允许写入，thinking关闭。脚本不带私钥，也不会自动发送编程任务。

当前机器已有“启动日志工具Pi.cmd”，继续双击即可；该文件会调用统一启动脚本。缺少Python或项目目录时会保留错误提示，而不是直接闪退。

## 日常操作

启动后直接显示项目、目录、最近任务和操作。输入具体编程需求会调用模型并可能计费；以下查看和反馈操作不调用模型：

```text
/harness home
/harness card
/harness card full
/harness rate 满意
/harness rate 需调整 这里填写真实调整意见
/harness rate 有问题 这里填写具体问题
/harness ratings
/memory list
```

卡片默认8行，避免长文件清单、版本和绝对路径挤满终端。`card full` 显示详细信息，并输出可在浏览器打开的HTML文件路径；该HTML包含变更清单、版本、反馈按钮与证据链接。`/harness guide` 输出完整使用页路径。

反馈保存前先核对确认框里的任务。满意只记录结果；其他反馈产生带理由和证据的待审建议。审阅不代表应用，不会自动改记忆或Skill。

## 如何判断完成

模型正常结束与独立验收通过是两回事。卡片把执行、测试数、代码指纹和保护文件结果分别显示。缺失信息为未验证；代码在验收后变化会提示需重新验证，不沿用旧的通过结论。用户满意也不代表工作流已进化。

## 排错与版本回退

- `widget truncated`：先看精简卡片，详细内容用 `card full` 或HTML；终端宽度很小时仍可能换行。
- `fd/ripgrep not found`：对应搜索工具未安装，不是任务卡片或启动失败；程序不会自动下载。
- 没有任务：确认启动页的用户、项目和工作目录；新项目本来就没有旧项目的记录。
- 找不到Python或项目：检查启动脚本与项目目录，不要新建一个空数据库冒充恢复记录。
- Skill回退：先检查组件和当前活动版本，再使用 `/harness package rollback 名称` 并确认。必须有父版本，初始v1不能回退；操作会切换会话，不删除原任务和证据。
- 实验评测和自动候选：仍需检查完整载荷、费用限制、独立结果与启用条件；本次收尾不自动启动它们。
