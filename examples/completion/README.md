# 任务完成卡片

任务结束时自动显示卡片，保留 `completed` / `failed` / `aborted` 等真实执行状态；完成不代表测试通过。不自动跑测试、调用模型、重试或升级Skill。

```text
/harness card
/harness card TASK_ID
```

卡片列出需求、已记录差异、模型、实际加载的Skill/coding版本、耗时、估算费用和下一步。HTML里可以打开完整JSON证据与证据编号。卡片保存在当前数据库旁的 `task-cards` 中，按用户/项目和任务隔离，不上传任何内容。

只有模型执行正常结束、独立测试通过且测试数非零、当前代码与验证指纹匹配、保护文件检查明确通过时，才标记完成。保护结果缺失显示“需要核对保护文件”；未验收或源码变化后显示“需要独立验证”。失败与违规显示对应修复建议。验证只覆盖记录声明的文本范围，不是完整仓库安全保证。

模型回复“测试通过”不计作验证；旧记录没有费用、版本、时间或保护结果时显示“未验证”，不会补零或套用当前活动版本。新原生任务通过 `message_end` 收集用量，费用是模型报告估算值；任何一次用量缺费用时总费用保持未知，已知部分另存字段。不会保存隐藏思维内容。

历史任务只有带明确来源的真实执行材料才能补充元数据。关键词过滤例子的模型耗时和费用来自已保存的真实运行报告，并关联原模型task_id、源报告路径及哈希；没有补造模型轨迹。

手动刷新卡片会重新检查已记录的源码指纹，但不会重新执行测试。新卡片使用不同哈希路径，旧卡片作为当时的快照保留；查看当前状态请重新运行 `/harness card`。

## 任务反馈与建议

```text
/harness rate 满意
/harness rate 需调整 请在使用说明里增加中文例子
/harness rate 有问题 关键词过滤的结果与我的预期不同
/harness ratings
```

命令默认关联当前会话最近任务，没有会话记录时选择当前用户/项目最新任务；保存前显示任务ID、需求和反馈，请核对后确认。负面反馈必须填写说明。可在说明前显式指定 `memory` 或 `workflow`，例如 `rate 需调整 memory 后续示例同时说明预期输出`；默认仅建议处理本任务，不猜测长期偏好。

HTML卡片有“满意、需要调整、执行有问题”三个按钮。可填写说明和建议范围，点击后只生成/复制一条绑定task_id的JSON命令，粘贴到Pi确认才保存；静态文件本身不能写数据库。无需模型调用。旧HTML是历史快照，先用 `/harness card` 生成新版。

每条反馈保存为用户报告并关联原任务。满意只记录结果，产生“暂不改进”的记录，不写记忆，不宣称进化成功。其他反馈由本地规则生成带证据编号、理由和内容的pending建议；测试通过与用户不满意可以同时存在，原验收不被覆盖。

```text
/harness suggestion review 建议ID 1
/harness suggestion reject 建议ID 1
```

审阅后状态为 `reviewed_not_applied`，拒绝为 `rejected`。修订号必须与当前状态一致；同一提交request_id可安全重试，不能换内容复用。所有操作检查用户、项目和任务范围。此入口不提供自动应用：记忆草案仍需另行确认，工作流假设仍需独立评估，才能进入现有版本机制。它不会自动创建/启用Skill或修改AGENTS.md。
