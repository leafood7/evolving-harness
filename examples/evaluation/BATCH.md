# 分阶段重复评测

这是评测基础设施，不是“进化有效”的结论。现有失败记录不会被新批次覆盖，也不会自动升级 Skill。

运行限制分为整批和单组。`max_seconds`、`max_arm_runs`、`max_estimated_cost` 属于整批；`max_tokens` 和 `max_model_messages` 也是整批累计量，可显式设为 `null`。关闭Token限制并不会自动关闭消息限制。新增可选 `max_arm_model_messages` 对每组分别计数，达到时保存该组的失败/无结论，不重试；用量已记录的情况下继续后面的组。费用、Token或整批消息到限，以及用量不完整仍停止整批。

建议用 `max_model_messages: null` 配合 `max_arm_model_messages: 48` 明确表达“每组最多48条”，而不是把48误当成整个批次的额度。这个值不是收益结论，下一次真实实验仍需提前确认。预览和报告会显示两层限制；整批消息额度小于所有组的单组额度之和时给出提示，不会暗中提高限制。

单组模型请求现有超时100秒，模型作用域超时115秒；独立验收另有每条10秒限制，同时服从整批活动时间。单组超时会标记 `arm_model_timeout`，不算代码能力退化证据。若超时时还有未返回用量，停止后续组，避免把未知费用当作零。

新准备的任务使用有效的Python测试模块名，例如 `tests/test_task_dev_01.py`，并明确告知副本不含Git元数据、当前可用工具。新任务若新增含连字符等无效模块名的 `tests/test*.py`，验收会报告 `undiscoverable_test_filename`，避免仅因原有测试通过就忽略被跳过的新测试。这个检查不证明所有新断言都执行；旧冻结任务保留原有规则，不会追改历史分数。

本机离线演示（输出目录必须尚不存在；模拟模型与用量，独立 Python 验收真实执行）：

```text
python examples/evaluation/batch_offline_demo.py --output outputs/batch-demo
```

复制 `batch.example.json` 为自己的配置，修改 `candidate`、模型以及任务。示例两题是已公开教学题，不能算正式未见测试集。每题 `source` 相对于配置文件目录；不得使用 `..`。验收 Python 代码是可信用户配置，会以用户权限运行。

```text
/harness batch prepare examples/evaluation/batch.local.json
/harness batch run
/harness batch status
/harness batch report
```

准备不调用模型。`run` 展示并保存当前阶段完整载荷，确认后执行该阶段所有待运行对照，每对分别执行基线和候选；固定 provider/model、思考关闭、无自动重试、无自动加载个人记忆。每次重复使用新的代码副本和 Pi 会话。每完成一对更新进度，HTML/JSON 含逐次验收、工具调用、时间、估算费用与人工干预。次数上限按两组预留，不会为了凑次数只开启半对。

开发题全部结束后，查看报告，再决定是否开放预留题：

```text
/harness batch unlock
/harness batch run
```

开放需要单独确认，并记录任务指纹；同一用户/项目下已经开放过的任务不能再作为新批次的未见题。只拦截内容完全相同的任务，不能检测语义近似或人工泄漏。预留题存在独立阶段数据库，开发题载荷和复盘事件中不含预留题内容。文件仍在本机，逻辑隔离不等于操作系统沙箱。

人工帮助需如实记录；记录不会替你修改代码或向模型发送消息。在报告中找 ENTRY ID，运行：

```text
/harness batch note ENTRY candidate correction 我指出了错误的导入路径
```

支持 `baseline` / `candidate`，类别 `clarification`、`correction`、`manual_edit`、`takeover`。报告分开列出独立验收通过数和“无已声明帮助的通过数”。无法检测未申报帮助；有干预的批次不能作为自动通过的晋升证据。

`/harness batch stop` 在对照边界停止后续执行；当前运行由超时结束，不能承诺即时中断。桥接进程意外中断后，330秒租期到期的报告会标记中断，禁止自动重跑。需要重新设计实验时创建新批次，旧失败仍保存。

运行次数可以事先限制；Token、模型消息数和费用由返回事件监测，收到事件时可能已经超过阈值。费用是模型报告的估算值，不是账单封顶。用量或费用缺失时停止后续运行，不能把缺失当零。总时间按活动执行时间累加，不计等待人工确认；进程清理可能稍有超时。

源码、Skill内容、指令、验收和运行入口指纹在准备时冻结。运行时代码、模型或预览发生变化会拒绝执行。指纹不覆盖全部依赖，也无法冻结远端模型权重。完整报告不会自动启用候选。对照只有基线/候选两组；正式 A/B/C 研究需另行设计互不混用的实验，不能把本功能当作已完成三组研究。
